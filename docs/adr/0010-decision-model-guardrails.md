# ADR-0010: Ограничения работы с decision-моделями

Статус: proposed · Дата: 2026-11-16 · Источник: `docs/review/01-findings.md` F-05, F-06, F-07, F-08

Уточняет (amends) [ADR-0006](0006-decision-models.md): отдельный порт `Decision` и
политика поверх провайдера остаются в силе. Отменяется допущение, что закреплённый
id модели гарантирует воспроизводимость, и что локальные веса — равноценная замена
облачной модели.

## Контекст

Проверка по первоисточникам (2026-11-16) показала:

- **Формат на проводе** в `04-providers.md §10` расходится с API вендора: варианты
  передаются в `criteria`, а не в `options`; ответ `noul` — число от 0 до 1, без
  распределения; изображения — поле `images` (до 8) или multipart `assets`;
  специальный заголовок необязателен. Батч до 1024 запросов — свойство локального
  сервера, у облачного API отдельный асинхронный Batches.
- **Модель меняется под тем же id.** Drex Max v1.1 заменил исходный Drex Max «in
  place under the same id»; снятые с обслуживания id отвечают моделью-преемником.
- **Лицензия открытых весов** (Nace.AI Open RAIL-M, Attachment A) запрещает
  использовать модель и её вывод, чтобы «provide medical, legal or financial advice
  or decisions without appropriate qualified human oversight», обязывает переносить
  ограничения всем получателям и запрещает использование организациям с выручкой или
  финансированием свыше $1M и конкурентам лицензиара. Drex DLM — CC BY-NC 4.0.
  У Drex Max v1.1 открытых весов нет.
- **Цена** в ресёрче записана с ошибкой единицы: $42 за 1M вместо $0.042 за 1M.

## Решение

1. Контракт и conformance-фикстуры decision-провайдера пишутся по документации
   вендора, а не по примеру из спеки v0.1. Пример в `04-providers.md §10`
   исправляется в M0.
2. В журнал пишется **фактическая модель из ответа** и время; калибровка и пороги
   привязаны к тройке «фактическая модель × версия вопросов × вопрос».
3. Смена фактической модели при неизменном запрошенном id — событие
   `decision.model_changed`: пороги помечаются непроверенными, входы по этой модели
   переводятся в shadow до накопления новой калибровки или явного подтверждения
   пользователя.
4. Реплей «как было» воспроизводит только записанный ответ. Обещание «одинаковый
   вход — одинаковое решение» распространяется на ядро, но не на вендора.
5. **Веса моделей не входят в поставку.** Пользователь скачивает их сам и принимает
   лицензию вендора; приложение показывает её ограничения при подключении.
6. Для провайдера на локальных весах под Open RAIL-M вход исполняется **только через
   approve человека**. Автоматический вход разрешён лишь для провайдеров, чьи условия
   это допускают; условия облачных API Nace и TypeSafe должны быть прочитаны до M3 —
   сейчас они неизвестны.
7. Облачная и локальная модели считаются разными моделями с раздельной калибровкой;
   локальная не является автоматическим fallback для облачной.
8. Цены — за 1B токенов decimal-строкой (см. ADR-0009).

## Последствия

- Появляется фича, которой нет у аналогов: предупреждение о подмене модели.
- `decision-local` перестаёт быть «офлайн-страховкой» и становится отдельным
  провайдером с обязательным approve. Бюджет «p95 < 150 мс» из
  `01-architecture.md §11` для него не действует и подлежит замене на измеренный.
- Fully-automatic режим зависит от условий вендора — это внешний риск, который
  фиксируется в списке рисков плана.

## Альтернативы

- **Доверять закреплённому id.** Отклонено: опровергнуто практикой вендора.
- **Бандлить квантованные веса для удобства.** Отклонено: распространение требует
  переноса ограничений лицензии и несовместимо с автоматической торговлей.
- **Отказаться от decision-моделей в пользу LLM.** Отклонено: LLM дороже на порядки
  и не даёт распределения вероятностей, на котором строится калибровка.
