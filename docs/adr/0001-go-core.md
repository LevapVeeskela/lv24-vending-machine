# ADR-0001: Go как язык ядра

Статус: accepted · Дата: 2026-11-16

## Контекст

Нужно выбрать язык для core + CLI (`vend`, `vendd`): высокая конкурентность
(много WS-подписок), быстрый цикл разработки, простые бинарники под Win/macOS/
Linux, лёгкая замена провайдеров, приемлемая производительность для бэктестов.

Кандидаты: Go, Rust.

## Решение

**Go 1.27.**

## Обоснование

1. Консистентность с `lv24-brain`: та же архитектура (ports/adapters, registry,
   CLI + локальный сервер), тот же опыт, переиспользуемые паттерны и код.
2. Скорость итераций выше: провайдер пишется за часы, а не дни; меньше времени
   на борьбу с borrow checker в коде, который в основном I/O-bound.
3. Конкурентность без async-колорита: WS-подписки, таймеры, OMS — естественно
   ложатся на горутины/каналы.
4. Один статический бинарник, простая кросс-компиляция, малый размер, быстрый
   старт — важно для CLI и sidecar в Tauri.
5. `oapi-codegen` + drift-тест уже отработаны в `lv24/main/ai-gateway`.
6. Экосистема: `wazero` (WASM без CGO), `modernc.org/sqlite` (без CGO),
   `pgx`, `decimal`, `slog`.

## Последствия

- Тяжёлые вычисления (оптимизация параметров, ML-инференс, криптография
  подписи) выносятся в отдельные модули/процессы с контрактом; язык модуля не
  диктует язык ядра.
- WASM-рантайм стратегий — `wazero`; если упрёмся в производительность,
  заменим на Rust-рантайм за стабильным ABI.
- Нет дженерик-магии: расширяемость через интерфейсы, реестр и кодоген, а не
  через макросы.

## Альтернативы

- **Rust**: лучше предсказуемость latency и типы, но дороже разработка,
  сложнее плагинная модель и WASM-хостинг, меньше готовых коннекторов; команда
  и существующие проекты — Go. Рассмотреть для отдельных hot-path модулей.
- **TypeScript/Node**: быстрее в UI-слое, но слабее в конкурентности и
  долгоживущих процессах, тяжелее бинарники.
- **Python**: богатая экосистема для ресёрча, но не для ядра с жёсткими
  таймингами и единым бинарником.
