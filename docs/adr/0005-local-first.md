# ADR-0005: Local-first и Tauri-шелл с sidecar-ядром

Статус: accepted · Дата: 2026-11-16

## Контекст

Продукт должен работать у одного пользователя на ноутбуке (без сервера и
подписок), но тот же код должен масштабироваться в серверный режим. Desktop
планируется «как lv24-brain»: Tauri + React + локальный демон.

## Решение

1. Ядро `vendd` — отдельный процесс с HTTP/SSE API. Оно не встраивается в
   Tauri-процесс.
2. Desktop (Tauri) супервизит sidecar: динамический порт, per-session токен,
   health-gate, restart с backoff, kill-tree и чистка сирот на выходе.
3. Хранилище — один порт, два адаптера: SQLite (WAL) локально, Postgres на
   сервере. Одна схема миграций.
4. Доменные данные клиенты получают только через OpenAPI/SSE. Tauri-команды —
   только нативные (трей, обновления, keychain, deep-link, файлы).
5. Секреты — в ОС-keychain; webview их не видит.

## Последствия

- Один и тот же React-код работает в desktop и web без ветвлений.
- Ядро можно запустить headless (сервер, CI, бэктест) без GUI.
- Появляется ответственность за жизненный цикл процессов (супервизия, порты,
  токены) — закрывается тестами и логированием.
- SQLite и Postgres требуют дисциплины по типам (decimal, timestamptz, ULID).

## Альтернативы

- **Ядро внутри Tauri (Rust)**: меньше процессов, но доменная логика на Rust,
  нельзя headless-сервер и CI-бэктест тем же бинарником.
- **Только облако**: проще эксплуатация, но нарушает local-first и приватность
  ключей.
- **Только SQLite**: не масштабируется на multi-user сервер.
