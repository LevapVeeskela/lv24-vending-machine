# ADR-0002: Contract-first и кодогенерация

Статус: accepted · Дата: 2026-11-16

## Контекст

Один и тот же API и одни и те же модели потребляют Go-ядро, React-клиенты
(desktop/web) и Flutter-приложение. Ручное дублирование типов уже приводило к
расхождениям в других проектах.

## Решение

Единственный источник правды — `contracts/`:

- OpenAPI 3.1 для REST/SSE (`contracts/openapi/core-v1.yaml`);
- JSON Schema для событий, манифестов агентов, дескрипторов провайдеров,
  proposal и риск-политик.

Генерация в Go (`oapi-codegen`, `go-jsonschema`), TS (`openapi-typescript`,
`json-schema-to-typescript`) и Dart (`openapi_generator`, `quicktype`).
Сгенерированный код коммитится, CI перегенерирует и падает на diff.

## Последствия

- Любое изменение контракта — отдельный шаг с ревью и drift-тестом.
- Нельзя «быстро поправить» сгенерированный тип: правится схема.
- Обратная совместимость: только аддитивные изменения в `v1`, события несут
  `schemaVersion`, неизвестные поля игнорируются.
- Клиенты не пишут ручные DTO для API-границы.

## Альтернативы

- **Protobuf/gRPC для всего**: строже и быстрее, но хуже для браузера и отладки,
  больше инфраструктуры; оставляем для v2-паков провайдеров.
- **Ручные типы**: быстрее на старте, гарантированно разъедется на трёх языках.
- **Единый TS-монолит**: не покрывает Go/Dart.
