# ADR-0009: BYOK и предмет продажи

Статус: proposed · Дата: 2026-11-16 · Источник: `docs/review/01-findings.md` F-02, F-03, F-09, F-20

Уточняет (amends) [ADR-0007](0007-license-and-stores.md): лицензия MIT и запрет
AGPL/GPL остаются в силе; меняется место исходников платной сборки и момент, когда
мобильное приложение становится источником выручки.

## Контекст

В спеке v0.1 нет бизнес-модели. Единственное упоминание продажи — мобильное
приложение (ADR-0007). При этом:

- значения по умолчанию для LLM-бюджета дают до $300 в месяц на пользователя
  (`02-monorepo.md:183`); при подписке около $10 это убыток, если платим мы;
- мобильное приложение по плану лежит в публичном MIT-репозитории
  (`02-monorepo.md:83`): его можно собрать бесплатно;
- App Store требует, чтобы приложения для торговли подавала организация,
  оказывающая финансовые услуги (guidelines 3.2.1(viii), 5.1.1(ix)), а разблокировка
  функций шла через встроенные покупки (3.1.1).

## Решение

1. **BYOK.** Ключи LLM и decision-провайдеров — пользовательские. Мы не перепродаём
   токены и не проксируем запросы. Бюджеты в приложении — защита пользователя от
   собственных расходов, а не наш биллинг.
2. **Гейт «только на сигналы входа» — режим по умолчанию.** Опрос модели на каждой
   свече включается явно, с показом прогноза расходов за месяц.
3. **Цены хранятся за 1B токенов decimal-строкой**; расчёт покрыт тестом на примере
   из документации вендора.
4. **Мы ничего не хостим для пользователя в v1**: ни ключей, ни состояния, ни relay.
5. **Предмет продажи выбирается на этапе M5** по данным клина и live. Кандидаты:
   pro-отчёты и арена моделей, подписанные сборки, настройка гейтов под заказ,
   мобильный пульт. До M5 продукт бесплатен.
6. **Исходники платной store-сборки** — в отдельном приватном репозитории, если
   владелец не выберет осознанно модель «открытый код, платят за удобство».
7. **Мобильное приложение не планируется как первый источник выручки** и не
   начинается без юрлица и решения по географии.

## Последствия

- Себестоимость ИИ на пользователя для нас равна нулю; рост цен вендоров — риск
  пользователя, о котором приложение обязано предупреждать.
- Порог входа выше: нужен собственный ключ вендора. Для целевого пользователя
  (разработчик с работающим ботом) это приемлемо.
- Без хостинга нет статуса оператора персональных данных по 152-ФЗ в v1. Появление
  relay или аккаунтов пересматривает это отдельным ADR.
- Регистрация разработчика в App Store — платная; решение о ней принимает владелец
  вместе с решением о mobile.

## Альтернативы

- **Включить ИИ в подписку.** Отклонено: расход на пользователя не ограничен сверху
  и зависит от чужого прайса.
- **Хостинг ботов (SaaS).** Отклонено для v1: кастодиальное доверие, поддержка и
  регуляторика, которых у одного разработчика нет; остаётся non-goal.
- **Сразу платная мобилка.** Отклонено: ей нечем управлять до M3, и она упирается в
  правила сторов.
