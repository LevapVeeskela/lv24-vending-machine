# 00. Продукт и границы

Статус: draft v0.2 (scope сужен ревью, ждёт решения владельца) · Владелец: LevapVeeskela · Дата: 2026-11-16
Обоснование изменений: `docs/review/00-verdict.md`, ADR-0008…0010

## 1. Что это

**LV24 Vending** (`lv24-vending-machine`) — платформа автоматической торговли на
крипто-биржах и у брокеров, где торговые решения принимает связка
«детерминированное ядро + сменные ИИ-агенты».

Метафора вендингового автомата: пользователь один раз настраивает правила,
провайдеров и роли агентов; дальше машина сама собирает рыночные данные,
принимает решения, проверяет их риск-фильтром и исполняет — с полным журналом
«почему так».

Ключевое отличие от типового «AI trading bot»:

1. **Ядро детерминировано.** Любое действие с деньгами — типизированная команда,
   исполняемая кодом. ИИ только предлагает (`Proposal`), никогда не вызывает
   биржу напрямую.
2. **Провайдер — пакет, а не ветка `if`.** Биржа, брокер, источник данных, LLM,
   decision-модель, нотификатор — отдельные Go-модули с дескриптором
   возможностей и фабрикой. Замена провайдера не трогает ядро.
3. **Агент — роль, а не промпт в коде.** Под фичи вендора (спот/фьючерсы/DEX/
   MT5/брокерский API) объявляется свой агент-пакет: какие данные читает, какие
   инструменты ему доступны, какой контракт ответа, какие лимиты.
4. **Решение можно объяснить и воспроизвести.** Каждый прогон агента и каждая
   проверка риска пишутся в журнал с хэшами входов, моделью, стоимостью,
   калибровкой и итоговым вердиктом. Реплей детерминирован.
5. **Local-first.** Один бинарник + SQLite на ноутбуке; тот же core — в серверном
   режиме с Postgres и мультипользовательским доступом.

## 2. Ролевые сценарии

| Роль | Что делает | Что критично |
|---|---|---|
| Соло-трейдер | Ставит бота/агентов на свои ключи, следит с desktop | Безопасность ключей, paper-режим, понятный «почему» |
| Квант-разработчик | Пишет стратегии и агентов, гоняет бэктесты | Контракты, детерминизм, SDK, скорость итераций |
| Владелец портфеля | Несколько счётов/бирж, лимиты, отчёты | Сводный P&L, экспозиция, риск-политики, аудит |
| Оператор (server) | Следит за несколькими инстансами | Метрики, алерты, approve-очередь, kill switch |
| Агент-разработчик | Подключает новую модель/вендора | Реестр провайдеров, capability-модель, conformance-тесты |

### 2.1 Первый пользователь и боль (v0.2)

Из пяти ролей первой обслуживается одна — **квант-разработчик с уже работающим
ботом**, который подключает decision-модель (Drex, Jev) как фильтр входов.

- **Боль:** он платит за токены и не знает, приносит ли фильтр деньги и можно ли
  верить уверенности модели; давать модели ключи биржи он не хочет.
- **Что получает первым:** shadow-гейт рядом со своим ботом и отчёт в деньгах —
  counterfactual PnL, калибровка, цена решения. Без ключей и ордеров.
- **Что не обслуживаем в v1:** трейдера, которому нужна «просто кнопка», владельца
  портфеля на нескольких биржах, оператора серверного инстанса.

Это гипотеза ревью. Она проверяется интервью до M0 и гейтом G1
(`10-roadmap.md`); остальные роли возвращаются после него.

## 3. Что входит в v1 (Scope)

> **v0.2.** Разделы 3.1–3.3 описывают целевую платформу. Состав v1 сужен
> (ADR-0008); действует таблица ниже, а всё, чего в ней нет, перенесено в M7.

| Область | В v1 | Вне v1 |
|---|---|---|
| Продукт | shadow-гейт и отчёт → paper → live | терминал для всех рынков |
| Venue | одна крипто-биржа, спот; вторая — к платному релизу | брокеры, фьючерсы, DEX, MT5, CCXT-мост |
| ИИ | decision-провайдер (Drex, Jev), роль gate; ключи пользователя | 7 ролей агентов, дебаты, память, LLM в контуре решения |
| Стратегии | `dca`, `trend`, внешние сигналы через `POST /v1/gate` | `grid`, `rebalance`, WASM, бэктест с walk-forward |
| Риск | RiskGate (13 проверок из 15), kill switch, approve, reconciliation | проверки экспозиции портфеля и ликвидности, shadow-политики |
| Клиенты | CLI, Telegram; desktop и mobile — условные этапы | web, OIDC, RBAC |
| Хранилище | SQLite | Postgres, серверный режим |

### 3.1 Ядро и CLI
- Один бинарник `vend` (CLI) + `vendd` (локальный демон/сервер).
- Подключение провайдеров, проверка ключей, health-check, ротация секретов.
- Рыночные данные: инструменты, свечи, стакан, сделки, тикеры (REST+WS).
- Счёт: балансы, позиции, ордера, история исполнений.
- Paper-режим «из коробки» (симулятор исполнения) и live-режим под явным unlock.
- Стратегии: встроенные (DCA, grid, trend/momentum, rebalance) + внешние WASM.
- Бэктест и walk-forward на тех же стратегиях, что и live (parity).
- Агенты: analyst, critic, risk, executor, venue-specialist; LLM и decision-модели.
- Риск-гейт, kill switch, approve-очередь, reconciliation с биржей.
- Журнал решений и сделок, экспорт, реплей.

### 3.2 Клиенты
- **Desktop** (Tauri v2 + React): полноценный терминал — как `lv24-brain-desktop`.
- **Web** (React): те же экраны через общий `packages/ui-web`, серверный режим.
- **Mobile** (Flutter): портфель, боты, approve, kill switch, push, биометрия.

### 3.3 Провайдеры v1
- Крипто-биржи: минимум 2 (Binance, Bybit), затем OKX/Coinbase/Kraken.
- Брокеры: минимум 1 (Alpaca paper/live), далее IBKR, MT5-мост.
- Данные: собственные WS-коннекторы + резервный REST-провайдер (CCXT-совместимый).
- LLM: OpenAI-совместимый шлюз (все совместимые вендоры), Anthropic, Google,
  локальные (Ollama/llama.cpp) — через единый `LLMProvider`.
- Decision-модели: Drex (`/v1/systemone`), Jev (wire-compatible), локальная
  decision-модель как fallback.
- Нотификации: Telegram, webhook, desktop/mobile push.

## 4. Вне scope v1 (Non-goals)

- HFT, co-location, микросекундный арбитраж, FPGA.
- Маржинальная торговля сложными деривативами, опционы, структурные продукты.
- Кастодиальное хранение средств клиентов, юридическое управление активами.
- Copy-trading и социальная сеть.
- Мультиарендный SaaS с биллингом (архитектурно заложено, продуктом — позже).
- Гарантия доходности и «сигналы» как продукт.

Добавлено в v0.2 (ADR-0009, ADR-0010):

- Оплата ИИ за пользователя и перепродажа токенов: ключи LLM и decision-провайдеров
  — пользовательские.
- Хостинг чего-либо пользовательского в v1: ключей, состояния, relay для пульта.
- Поставка весов моделей вместе с приложением.
- Обещание неизменности модели на стороне вендора и защиты от вредоносного ПО на
  машине пользователя.

## 5. Продуктовые принципы

1. **Fail closed.** Сомнение в данных/провайдере/лимите → действие не исполняется.
2. **Paper by default.** Live включается явным действием с подтверждением и
   отображается в UI постоянно.
3. **Explain or don't trade.** Нет rationale/evidence у proposal — нет исполнения
   (для агентов, где объяснение включено политикой).
4. **Exit beats AI.** Стоп-лоссы, тейки и аварийное закрытие не зависят от
   доступности ИИ-провайдера.
5. **Замена без переписывания.** Любой провайдер/агент/стратегия меняется
   пакетом, ядро и клиенты не меняются.
6. **Один контракт — три языка.** Go/TS/Dart работают с одними схемами.
7. **Локально по умолчанию.** Облако — опция, а не требование.
8. **Сначала доказать пользу.** Гейт работает в shadow и показывает результат в
   деньгах до того, как ему доверят вход (v0.2).

## 6. Терминология

| Термин | Значение |
|---|---|
| `Venue` | Биржа/брокер/DEX, где исполняются ордера |
| `Provider` | Пакет-адаптер: venue, market data, LLM, decision, notifier, store |
| `Instrument` | Торговый инструмент (BTC/USDT, AAPL, EURUSD) |
| `Strategy` | Детерминированный генератор сигналов (код/WASM) |
| `Agent` | ИИ-роль с типизированным выходом; не имеет права на side-effect |
| `Proposal` | Предложение действия от стратегии/агента |
| `RiskGate` | Детерминированный фильтр, обязательный для любого действия |
| `Decision` | Зафиксированный вердикт: proposal + risk + approval + итог |
| `Run` | Экземпляр бота/стратегии/агента с конфигом и состоянием |
| `Mode` | `paper` \| `live` (плюс `dry-run` для агентов без ордеров) |
| `Journal` | Append-only поток событий: решения, ордера, филлы, риск, ошибки |
| `Pack` | Пакет провайдера/стратегии/агента, подключаемый в рантайме |
