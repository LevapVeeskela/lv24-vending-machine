## 1. Принципы планирования

- Каждый этап заканчивается **работающим срезом** и **гейтом с числом**. Гейт не
  пройден — следующий этап не начинается.
- Сначала то, чего нет у аналогов, и то, что можно отдать без ключей и денег.
- Деньги и безопасность — раньше удобства: paper, risk gate, журнал и
  reconciliation появляются до первого live-ордера.
- Контракты — с первого дня; кодоген для языка — когда появляется его потребитель.
- Live-режим — отдельный этап с чек-листом, а не «галочка в настройках».
- Два режима оплаты ИИ (ADR-0009): свои ключи пользователя — с первого дня;
  провайдер LV24 как платный режим — с M5.
- Аудитория — весь мир, издатель — из Беларуси (ADR-0011); до M5 распространение
  без сторов.
- Никаких платных сервисов: публичный репозиторий, стандартные GitHub runners,
  self-hosted деплой.

## 2. Этапы

Оценки — недели одного разработчика с ИИ-агентами, вилка «оптимистично–реалистично».

### M0 — Клин: ядро (2–3 недели)

До кода: 10 интервью с пользователями Drex/Jev-ботов (3 дня).

| Работа | Результат |
|---|---|
| `contracts/`: JSON Schema для decision, gate, journal; генерация Go; drift-тест | источник правды |
| Исправить `04-providers.md §10` по документации вендора (ADR-0010) | контракт совпадает с API |
| `core/domain`: Decimal, Instrument, Candle, GateRequest, GateVerdict, ошибки | инварианты + тесты |
| `core/ports`: `Decision`, `Notifier`, `Store`; реестр с дескрипторами | два профиля одного адаптера |
| `decision-drex` с профилем Jev: таймаут, circuit breaker, валидация распределения | conformance на фикстурах вендора |
| `core/store`: SQLite, миграции, journal append + hash-chain | `vend journal verify` |
| Публичные свечи одной биржи (REST, без ключей) | разметка исходов |
| CLI: `init`, `doctor`, `version`, `config`, `gate test` | работает на Win/mac/Linux |
| CI: contracts, core, lint, path-фильтры | PR-гейт |

**Приёмка:** `vend gate test` возвращает вердикт на записанных фикстурах; журнал
проходит `verify`; бинарники собираются под три ОС; контракты не дрейфуют.

**Kill:** адаптер не удаётся привести к документации вендора; ≥ 3 из 10 интервью
отвечают «не нужно».

### M1 — Клин: ценность (2–3 недели)

- `POST /v1/gate` (локальный, bind `127.0.0.1`): сигнал входа → вердикт с причинами.
- Shadow-режим: вердикты пишутся, ничего не исполняется.
- Встроенный источник сигналов `trend` для тех, у кого нет своего бота.
- Разметка исхода через N баров; отчёт: counterfactual PnL отклонённых и пропущенных
  входов, Brier, ECE, reliability-кривая, цена решения.
- Арена: один state в две модели, сравнение на данных пользователя.
- Событие `decision.model_changed` и алерт (ADR-0010).
- `notify-telegram`: алерты и недельная сводка.
- Рецепты: Freqtrade (пример пользовательской стратегии), TradingView webhook.
- Quickstart на английском и русском, релизные бинарники, команда
  `vend gate report --share`.

**Приёмка:** внешний пользователь ставит и получает первый вердикт за 15 минут;
shadow работает 7 суток без вмешательства; отчёт воспроизводится из журнала.

**Гейт G1 (день 30, пересмотр на день 44):** число внешних инсталляций с ≥ 7 днями
непрерывной работы и ≥ 100 размеченными решениями.
≥ 20 — M2; 5–19 — одна итерация на 2 недели; < 5 — **стоп или пивот**.

### M2 — Paper и риск (4–7 недель)

| Работа | Результат |
|---|---|
| Адаптер одной биржи: спот, REST + WS, `InstrumentRegistry`, `ConnectionSupervisor` | инструменты, свечи, стакан |
| `paper` venue: fill model, комиссии, слиппедж, две книги | paper-исполнение |
| OMS: intent → reserve → submit → reconcile, идемпотентность | без дублей |
| RiskGate v1: 13 проверок из 15 (без 12 «экспозиция портфеля» и 13 «ликвидность») + YAML-политики + `risk simulate` | стабильные коды отказа |
| Стратегии `dca`, `trend`; `StrategySpec` | параметры из спеки |
| Reconciliation на старте и после реконнекта; kill switch | чистое состояние после рестарта |
| CLI: `market`, `account`, `order`, `run`, `risk` | сценарий целиком в терминале |

Порядок проверок и коды отказа — как в `06-risk-execution.md §3.1`; проверки 12 и 13
добавляются позже аддитивно.

**Приёмка:** `trend` с гейтом крутится 14 суток на живых данных в paper; 0 дублей
ордеров; reconciliation чистый после рестарта; `vend risk simulate` объясняет каждую
блокировку; реплей детерминирован.

**Гейт G2:** приёмка выполнена и ≥ 30% пользователей клина перешли на paper-запуски.
Иначе — остаёмся продуктом-гейтом и не идём в исполнение.

### M3 — Live-минимум (3–6 недель)

- Live-исполнение на той же бирже, user data stream.
- Approve и kill в Telegram; live-unlock с TTL и подтверждением; `flatten`.
- Ключ с правом вывода средств — отказ для live, а не предупреждение.
- Reconciliation hardening: startup rebuild, sweep, orphan aging, дедуп филлов.
- Модель угроз (1 страница), дисклеймер и условия использования, политика поддержки,
  `vend support bundle` с редактированием секретов.
- Условия облачных API decision-вендоров прочитаны; режим human-in-the-loop для
  локальных весов (ADR-0010).
- Проверено руками: владелец из РБ может выпустить API-ключ выбранной биржи для
  собственного live-теста; получена консультация по регулированию в РБ (ADR-0011).
- Чек-лист `06-risk-execution.md §13` как gate.

**Приёмка:** 2 недели live на собственном счёте владельца на минимальном размере;
ни одного ордера в обход gate (проверяется журналом); kill switch и flatten
проверены на реальном счёте с нулевой позицией.

**Гейт G3:** за 30 дней после релиза ≥ 3 внешних пользователя в live без
неразрешённых инцидентов. Любой ордер в обход gate — остановка live до разбора.

### M4 — Desktop-lite (5–9 недель, условный)

Начинается, только если ≥ половины активных пользователей просят UI.

- Tauri-шелл: sidecar-супервизия, typed IPC, трей, updater.
- Кодоген TS из `contracts/`.
- 5 экранов: обзор, запуски, решения и калибровка, подтверждения, провайдеры и
  настройки.
- Safety UX: PAPER/LIVE, kill switch, DangerActionDialog, approve-карточки.
- Экран «О программе / лицензии» с текстом NOTICE для `lightweight-charts`.

**Приёмка:** полный paper-сценарий из UI без CLI; kill switch срабатывает и виден;
падение ядра восстанавливается супервизором.

**Kill:** условие старта не выполнено — этап пропускается.

### M5 — Первые деньги (2–4 недели)

- Провайдер LV24 как платный режим (ADR-0009): подключение через реестр провайдеров;
  доработка шлюза идёт в проекте `lv24` и в оценку этапа не входит.
- До запуска режима: условия вендоров о перепродаже доступа, обработка персональных
  данных, приём платежей издателем из РБ.
- Цена и форма оплаты: ценовой эксперимент на действующих пользователях.
- Вторая биржа — условие платного релиза.
- Решения по издателю для сторов и по relay — отдельными ADR.

**Гейт G4:** 60 дней после M3 — есть хотя бы один платёж или предоплата. Нет —
проект остаётся бесплатным инструментом без дальнейших инвестиций либо закрывается.

### M6 — Mobile-пульт (6–10 недель, условный)

Начинается только после G4, при решённом вопросе об издателе и relay (ADR-0011).

- Google Play — первым; App Store — после проверки доступности для издателя из РБ.
- Пробная подача в стор — до написания второго экрана.
- Кодоген Dart из `contracts/`.
- 4 экрана: обзор, боты, подтверждения, алерты; push; биометрия.
- Store-готовность: privacy policy, account deletion, Data safety, возрастной
  рейтинг, экспортная декларация шифрования, декларация финансовых функций.

**Приёмка:** approve с телефона доходит до исполнения < 5 с; push по критичным
событиям; отзыв устройства мгновенно блокирует доступ.

**Kill:** стор отклоняет пробную подачу по требованиям к финансовым приложениям и
нет пути их выполнить.

### M7 — Экосистема (без срока)

Каждый пункт — только по запросу платящих пользователей.

- Провайдеры: OKX, Alpaca, IBKR, MT5-мост, DEX-адаптер, CCXT-мост.
- Стратегии: `grid`, `rebalance`, WASM ABI, бэктест-движок с walk-forward.
- Агенты: analyst, critic, supervisor; LLM-провайдеры; память; evals.
- Проверки RiskGate 12 и 13; shadow-режим политик.
- Web, OIDC, RBAC, Postgres; multi-tenant SaaS.
- MCP-контроль, marketplace паков, SDK.

## 3. Порядок и зависимости

```
M0 ─▶ M1 ─[G1]─▶ M2 ─[G2]─▶ M3 ─[G3]─┬─▶ M5 ─[G4]─▶ M6 (условный) ─▶ M7
                                      └─▶ M4 (условный, параллельно M5)
```

Критический путь: **M1 (отчёт, который пользователь хочет увидеть ещё раз)**.

## 4. Команда и параллелизация

| Поток | Кто | Когда |
|---|---|---|
| Интервью, решения по гейтам | владелец | M0, каждый гейт |
| Контракты + core | владелец + агенты | M0–M2 |
| Адаптер decision, отчёт | владелец (критично) + агенты | M0–M1 |
| Адаптер биржи | агенты, ревью владельца | M2, M3 |
| Desktop UI | агенты (FSD-слайсы) | M4 |
| Mobile | агенты | M6 |

Правило: критичный код (risk, OMS, contracts, security) — только с ревью
владельца; остальное — по чек-листам и conformance-тестам. При реализации адаптеров
в контексте агента — только MIT/Apache-референсы (F-22).

## 5. Риски

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Гейт не улучшает результат | высокая | критическое для тезиса | это и проверяет клин; отрицательный результат публикуется |
| Вендор decision-модели меняет цену, модель, условия | высокая | высокое | два профиля, запись фактической модели, алерт, BYOK |
| Мало пользователей клина | средняя | высокое | интервью до кода, порог зафиксирован заранее |
| Отказ сторов издателю из РБ | высокая для Apple, низкая для Google Play | высокое для mobile | mobile условный; Google Play первым; пульт в Telegram |
| Режим LV24: условия вендоров, платежи и персональные данные | средняя | высокое для выручки | проверить до M5; режим со своими ключами работает независимо |
| Инцидент с деньгами пользователя | средняя | критическое | свой счёт первым, минимальный размер, ключ без вывода, дисклеймер |
| Нестабильность и блокировки API биржи | высокая | среднее | клин не зависит от ключей; вторая биржа до платного релиза |
| Ошибка в риск-гейте | средняя | критическое | property-тесты, ревью владельца |
| Утечка ключей | низкая | критическое | keychain, отказ при праве вывода, redaction |
| Лицензионное заражение | средняя | высокое | allowlist лицензий; AGPL/GPL-клоны не в контексте агентов |
| Рост scope | высокая | среднее | гейты; вырезанное — только в M7 |
| Выгорание | средняя | высокое | этапы по 2–7 недель с решением «дальше или стоп» |

## 6. Критерии «v1 готов»

- [ ] Клин: гейт, shadow, отчёт с калибровкой и counterfactual PnL.
- [ ] Одна биржа, спот: paper и live; вторая — к платному релизу.
- [ ] Risk gate + kill switch + approve в Telegram + reconciliation в проде.
- [ ] Decision-модель: два профиля, запись фактической модели, бюджеты.
- [ ] Журнал с hash-chain, экспорт, реплей, `support bundle`.
- [ ] Документация: quickstart, runbook, security и модель угроз, условия использования.
- [ ] CI зелёный, релизы подписаны (или явно unsigned), SBOM.
- [ ] Гейты G1–G3 пройдены; 30 дней live без критических инцидентов.

Desktop и mobile в критерии v1 не входят: они условные.

## 7. Критерии закрытия проекта

Любое из:

1. G1 не пройден после одной итерации.
2. На 60 днях собственных данных гейт не улучшает результат, и ни одна модель не
   откалибрована.
3. Ни на одной из двух выбранных бирж нельзя провести собственный live-тест, и нет
   доверенного тестировщика в другой юрисдикции.
4. G4 не пройден: 6 месяцев без первого платежа.

Отсутствие законного пути в сторы закрывает mobile, а не проект.
