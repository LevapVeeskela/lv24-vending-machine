# 03. План v0.2

Дата: 2026-11-16 · Заменяет последовательность из `docs/spec/10-roadmap.md` v0.1.
Основание: [находки](01-findings.md), [фичи](02-features.md). Решения — ADR-0008…0010
(статус proposed, ждут владельца).

## 1. Принцип пересборки

v0.1 шёл от фундамента к ценности: контракты → биржа → стратегии → ИИ → UI → live →
mobile. Отличие продукта появлялось на пятом месяце, первая выручка — после девятого.

v0.2 идёт от ценности к фундаменту: сначала то, чего нет ни у кого и что можно
отдать пользователю без ключей и денег, затем — только то, о чём попросили.

Каждый этап заканчивается гейтом с числом. Не прошли гейт — следующий этап не
начинается.

## 2. Клин на 30 дней (M0 + M1)

**Гипотеза.** Разработчики-трейдеры, у которых уже работает бот, поставят рядом
shadow-гейт на decision-модели, чтобы увидеть в деньгах, что дал бы ИИ-фильтр входов.

**Продукт клина.** Один Go-бинарник `vend` и Telegram-бот пользователя. Ключи биржи
не нужны, ордера не отправляются.

```
сигнал входа (Freqtrade / TradingView webhook / свой скрипт / встроенный trend)
        │  POST /v1/gate
        ▼
  decision-провайдер (Drex или Jev, ключ пользователя) ─▶ валидация распределения
        ▼
  политика гейта ─▶ вердикт ALLOW / REJECT / ABSTAIN + причины ─▶ журнал (SQLite)
        ▼
  разметка исхода по публичным свечам через N баров
        ▼
  отчёт: counterfactual PnL, калибровка, цена решения ─▶ CLI, HTML, Telegram
```

| Неделя | Работа | Результат |
|---|---|---|
| 0 (3 дня, до кода) | 10 интервью с пользователями Drex/Jev-ботов; страница «что получите» в README | список из ≥ 5 готовых попробовать |
| 1 | Контракты `decision`, `gate`, `journal` (JSON Schema → Go); журнал в SQLite; адаптер Drex с профилем Jev по документации вендора | `vend gate test` отвечает на записанных фикстурах |
| 2 | Загрузка публичных свечей; разметка исходов; встроенный источник сигналов `trend`; `POST /v1/gate` | shadow работает сутки без участия человека |
| 3 | Отчёт: counterfactual PnL, Brier, ECE, reliability, цена решения; арена из двух моделей; алерт о смене модели | `vend gate report` за 7 дней собственных данных |
| 4 | Telegram: алерты и недельная сводка; рецепты для Freqtrade и TradingView; quickstart; релизные бинарники | внешний пользователь ставит за 15 минут |

**Чего в клине нет:** ключей и ордеров, RiskGate, OMS, paper-брокера, стратегий кроме
`trend`, desktop, mobile, web, Postgres, LLM-агентов, WASM, кодогена TS и Dart.

**Деньги.** Токены на собственные прогоны — единицы долларов (расчёт в
`01-findings.md §3`). Платных сервисов нет: публичный репозиторий, стандартный CI,
GitHub Releases. Бюджет $3 000 не тратится; расходуется время.

**Одна метрика.** Число внешних инсталляций, где гейт отработал ≥ 7 дней подряд и
накопил ≥ 100 решений с размеченным исходом.

**Как измерить без скрытой телеметрии.** Отчёт содержит команду `--share`, которая
формирует обезличенную сводку (число решений, дни работы, метрики; без state,
инструментов и сумм) и предлагает опубликовать её в GitHub Discussions. Считаются
опубликованные сводки и подтверждения в личной переписке. При десятках
пользователей это проверяется вручную.

**Гейт G1 (день 30, пересмотр на день 44).**

| Результат | Решение |
|---|---|
| ≥ 20 инсталляций | продолжать, M2 |
| 5–19 | одна итерация на 2 недели по обратной связи, затем повторный замер |
| < 5 | стоп или пивот в настройку гейтов под заказ |

Порог 20 — не рыночная оценка, а минимум, при котором обратная связь перестаёт быть
анекдотом; владелец может изменить его до старта, но не после.

## 3. Этапы v0.2

Оценки — недели одного разработчика с ИИ-агентами, вилка «оптимистично–реалистично».

| Этап | Содержание | Недели | Kill-критерий |
|---|---|---:|---|
| **M0. Клин: ядро** | контракты decision/gate/journal, SQLite, адаптер Drex/Jev, публичные свечи, CLI `init`, `doctor`, `gate test` | 2–3 | адаптер не проходит фикстуры из документации вендора; ≥ 3 из 10 интервью говорят «не нужно» |
| **M1. Клин: ценность** | `POST /v1/gate`, shadow, разметка, отчёт K1+K2, арена K5, Telegram-алерты, рецепты, релиз | 2–3 | **G1**: < 5 инсталляций с 7-дневным удержанием |
| **M2. Paper и риск** | адаптер одной биржи (спот, REST+WS), paper-брокер, OMS, RiskGate из 13 проверок (без 12 и 13), `dca` и `trend`, reconciliation на старте, kill switch | 4–7 | **G2**: 14 дней paper — есть дубли ордеров или неразрешённые расхождения; < 30% пользователей клина перешли на paper-запуски |
| **M3. Live-минимум** | live на той же бирже, user data stream, approve и kill в Telegram, live-unlock, flatten, отказ при праве вывода, дисклеймер и политика поддержки, `support bundle` | 3–6 | **G3**: любой ордер в обход гейта по журналу; < 3 внешних пользователей в live на минимальном размере за 30 дней |
| **M4. Desktop-lite** (условный) | Tauri-шелл, 5 экранов: обзор, запуски, решения и калибровка, подтверждения, провайдеры и настройки; кодоген TS | 5–9 | начинать, только если ≥ половины активных пользователей просят UI; иначе пропустить |
| **M5. Первые деньги** | провайдер LV24 как платный режим (ADR-0009), ценовой эксперимент, вторая биржа как условие платного релиза, юридические тексты | 2–4 без доработки шлюза | **G4**: 60 дней после M3 — ни одного платежа или предоплаты |
| **M6. Mobile-пульт** (условный) | 4 экрана: обзор, боты, подтверждения, алерты; push; кодоген Dart; подготовка к сторам | 6–10 | начинать только после G4 и решения об издателе и relay (ADR-0011); Google Play первым; пробная подача в стор до написания второго экрана |
| **M7. Экосистема** | брокеры, WASM, мультиагентность, MCP, marketplace, web и Postgres | без срока | каждый пункт — только по запросу платящих |

До первого live: 11–19 недель. До первой выручки: 13–23 недели без desktop.
Для сравнения, v0.1 до live — 13–17 недель по собственной оценке и 29–45 по
оценке ревью (§4), до выручки — после M6.

## 4. Оценка v0.1 против реалистичной

| Этап v0.1 | План, нед | Оценка ревью, нед | Почему |
|---|---:|---:|---|
| M0 | 1–2 | 2–4 | кодоген на три языка с drift-тестом и CI под три ОС |
| M1 | 2–3 | 6–9 | адаптер биржи с WS и reconciliation — основная работа (F-12) |
| M2 | 2 | 4–6 | детерминированный бэктест с parity и WASM-ABI |
| M3 | 3 | 5–8 | рантайм агентов, бюджеты, evals |
| M4 | 3–4 | 8–12 | 13 экранов, sidecar-супервизия, updater, подпись |
| M5 | 2–3 | 4–6 | две биржи в live, hardening |
| M6 | 3–4 | 8–12 | web с OIDC и Postgres плюс mobile и три стора |
| **Итого** | **16–21** | **37–57** | |

Оценки ревью — экспертные; исторических данных по скорости владельца нет. Способ
проверить: фактическая длительность M0 клина задаёт коэффициент для остальных.

## 5. Топ-5 рисков плана v0.2

| # | Риск | Вероятность | Влияние | Мера |
|---|---|---|---|---|
| 1 | Гейт не улучшает результат: модель не откалибрована на рыночных вопросах | высокая | критическое для тезиса | это и есть проверка клина; отрицательный результат публикуем и закрываем ИИ-направление, а не подгоняем пороги |
| 2 | Вендор decision-модели меняет цену, модель или условия | высокая (уже было: модель заменена под тем же id) | высокое | два провайдера с первого дня, запись фактической модели, алерт дрейфа, BYOK |
| 3 | Пользователей клина слишком мало, чтобы отличить сигнал от шума | средняя | высокое | 10 интервью до кода; порог зафиксирован заранее; одна итерация и стоп |
| 4 | Регуляторный отказ в сторах или отсутствие юрлица | высокая для Apple | высокое для mobile, низкое для остального | mobile условный и последний; Telegram закрывает пульт; пробная подача рано |
| 5 | Инцидент с деньгами первого live-пользователя | средняя | критическое для репутации | свой счёт первым на 2 недели; минимальный размер; ключ без права вывода как жёсткое условие; дисклеймер и `support bundle` до M3 |

## 6. Что обещаем и что нет

| Обещаем | Не обещаем |
|---|---|
| Ни один ордер не уходит в обход детерминированных проверок | Доходность, сигналы, инвестиционные рекомендации |
| Ключи хранятся только на машине пользователя | Защиту от вредоносного ПО на этой машине |
| Выход из позиции не зависит от ИИ и от нас | Работу при недоступности биржи |
| Каждое решение можно поднять из журнала | Что журнал — доказательство для третьих лиц |
| Честный отчёт, включая отрицательный результат гейта | Что гейт улучшит результат |
| Предупреждение о смене модели вендором | Неизменность модели на стороне вендора |

## 7. Три вопроса владельцу

Ответы получены 2026-11-16 — см. §8. Ниже вопросы в исходной редакции.

1. **География и юрлицо.** Для кого продукт — РФ, Беларусь или глобально — и от
   чьего имени публикуемся? От этого зависят первая биржа, стор и сама возможность
   платной мобилки (F-03, F-24).
2. **Что продаём и кто платит за ИИ.** Согласны ли на BYOK? Что является платным:
   закрытая мобилка, pro-отчёты, подписанные сборки, настройка под заказ? Сколько
   стоит ваш месяц — без этого нет точки окупаемости (F-09, F-20).
3. **Готовы ли отложить desktop, mobile и live ради 30-дневного клина** и принять
   порог G1 до старта? Если «терминал» важнее проверки спроса — вердикт меняется с
   narrow на осознанный долгострой без kill-критериев.

## 8. Ответы владельца и что они меняют (2026-11-16)

| Вопрос | Ответ | Оформлено |
|---|---|---|
| География и юрлицо | Пользователи — весь мир; продукт издаётся из Беларуси | ADR-0011 (accepted) |
| Что продаём, кто платит за ИИ | Два режима: клиент платит сам (свои ключи или вход через свою подписку) либо через наш провайдер LV24, который доработаем позже и с которого берём деньги | ADR-0009, редакция 2 (accepted) |
| Клин вместо desktop, mobile и live | Да, если оно того стоит | ADR-0008 (accepted с условием) |

### Что изменилось в плане

- **M5** получил содержание: платный режим — провайдер LV24. В ядре это обычный
  провайдер из реестра, поэтому до M5 ничего строить не нужно. Доработка шлюза
  `lv24/main/ai-gateway` идёт в проекте `lv24` и в оценки этого плана не входит.
- **Язык по умолчанию — английский**, русский второй.
- **Сторы:** Google Play первым (регистрация разработчика и продавца из Беларуси
  поддерживается), App Store — после проверки, RuStore — дополнительный канал.
- **Критерий закрытия про API-ключи** переформулирован: мировой пользователь ключ
  получит; риск теперь в том, сможет ли владелец из РБ провести собственный live-тест.

### Что ответы не закрывают

1. **Наценка на decision-токены не даёт выручки.** При расходе $0.65 в месяц на
   пользователя наценка 30% — это $0.20. Режим LV24 зарабатывает либо фиксированной
   платой за доступ, либо на LLM-трафике. Форму оплаты нужно выбрать до M5; сейчас
   она неизвестна.
2. **Шлюз LV24 не покрывает клин.** По README он отдаёт `chat/completions` и не имеет
   эндпоинта decision-моделей; он не выпущен и не развёрнут. Клин и v1 до M5
   работают только на ключах пользователя.
3. **Вход через подписку вендора** в стороннем приложении разрешён не у всех
   вендоров. Условия не проверены; до проверки — только API-ключи.
4. **Перепродажа доступа к моделям** должна быть разрешена условиями Nace, TypeSafe и
   поставщиков LLM. Не проверено.
5. **Режим LV24 делает нас поставщиком услуги**: аккаунты, платежи и персональные
   данные пользователей из разных стран. Обязательства оформляются до запуска режима.
6. **App Store для издателя из РБ** — риск с двух сторон: правила для финансовых
   приложений и сообщения о блокировках аккаунтов, связанных с Беларусью
   (вторичный источник, официального подтверждения нет).
7. **Стоимость месяца владельца** не названа — точка окупаемости по-прежнему
   выражена формулой, а не числом.
8. **«Если оно того стоит»** — условие без числа. Его роль выполняют 10 интервью до
   кода и порог G1; владелец может изменить порог до старта M0.
9. **ADR-0010** (ограничения decision-моделей) владельцем не рассмотрен, остаётся
   proposed. Он влияет на контракты M0, поэтому решение нужно до их написания.

### Следующий шаг

10 интервью (3 дня, делает владелец) и, параллельно, M0: контракты decision, gate,
journal и адаптер Drex/Jev по документации вендора.
