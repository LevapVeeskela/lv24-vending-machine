# lv24-vending 0.1.0-m1 (RC)

**This is a pre-release.** `0.1.0-m1` is a release candidate; it is not the
stable release and `releases/latest` does not point at it.

LV24 Vending is a local shadow gate for trading signals. Your bot sends an entry
signal to the loopback API, the gate asks a decision model for a second opinion,
and the verdict is written to a hash-chained journal. Later the gate labels the
entry from closed candles and reports whether filtering the signal would have
helped or hurt. **It never places an order**: this release has no execution
path, no OMS and no live trading. `live` is rejected by config validation.

## Release files

The pre-release carries five plain executables (not archives), the license text
and a checksum manifest:

```text
vend_windows_amd64.exe
vend_linux_amd64
vend_linux_arm64
vend_darwin_amd64
vend_darwin_arm64
LICENSE
NOTICE
SHA256SUMS
```

Download the binary for your platform together with `SHA256SUMS`, `LICENSE` and
`NOTICE`, and put them in one directory. `LICENSE` and `NOTICE` travel with the
binaries because Apache-2.0 requires both.

## Verify the checksum

`SHA256SUMS` is a plain manifest, one line per file in the form
`<sha256>  <filename>`. A mismatch means **do not run the file**: download it
again and re-check.

Linux (GNU coreutils):

```bash
sha256sum -c SHA256SUMS --ignore-missing
# vend_linux_amd64: OK
```

macOS:

```bash
shasum -a 256 vend_darwin_arm64
# <sha256>  vend_darwin_arm64
```

Compare the printed hash with the line for the same file name in `SHA256SUMS`.

Windows PowerShell:

```powershell
(Get-FileHash .\vend_windows_amd64.exe -Algorithm SHA256).Hash.ToLower()
# <sha256>
Get-Content .\SHA256SUMS
```

Compare the printed value with the line for `vend_windows_amd64.exe`.

## Unsigned binaries

The binaries are **not code-signed and not notarized**. The SHA-256 manifest is
the only integrity check; a platform warning is expected and is not by itself
proof of tampering. Do not bypass a warning on a file whose checksum you have
not verified.

### macOS Gatekeeper

A downloaded binary gets the `com.apple.quarantine` attribute:

```bash
xattr -l ./vend
# com.apple.quarantine: ...
```

Options, in order of preference:

1. In Finder, right-click (or Control-click) `vend` → **Open** → **Open** in the
   dialog. macOS remembers the choice for that file.
2. If the dialog only offers **Cancel**, open **System Settings → Privacy &
   Security**, find the blocked `vend` message and click **Open Anyway**.
3. Remove the attribute explicitly after verifying the checksum:

   ```bash
   xattr -d com.apple.quarantine ./vend
   ```

Gatekeeper does not replace the checksum check; do both.

### Windows SmartScreen

The first run may show **"Windows protected your PC"**:

1. Click **More info**.
2. Click **Run anyway**.

If the file came from a browser download it may also carry the
Mark-of-the-Web; after verifying the hash you can clear it:

```powershell
Unblock-File .\vend.exe
```

There is no Authenticode signature yet, so SmartScreen keeps warning until the
binary is signed in a later release.

### Linux

There is no Gatekeeper equivalent. `chmod +x` is required; some file managers
also need "Allow executing file as program" in the file properties.

## What you need

- **Your own decision-provider key** for `decision-drex` (Drex or Jev profile).
  The key is yours (BYOK); the binary calls your provider directly. The key is
  read from a `VENDING_SECRET_*` environment variable and is never written to
  the config, the journal or the logs. `vend demo` needs no key.
- **Candles are public.** The default `marketdata-binance` provider reads the
  public Binance Spot klines endpoint and needs no key.

## Where to start

See it first, without a key and without network access:

```bash
go build -o vend ./core/cmd/vend
./vend demo
```

`vend demo` writes a synthetic week into a temporary journal and prints the full
report; every major section is marked `SYNTHETIC — not real market data`. It is not G1
evidence: `status` and `report` show `g1: 0/100, 0/7`, and `gate report
--share` refuses the journal. It needs no key and no network.

Then:

- [Quickstart](https://github.com/LevapVeeskela/lv24-vending-machine/blob/main/docs/quickstart.md)
  — `vend demo` in 60 seconds, or your own gate in 5 minutes with
  `vend init --quick`, the two secret exports and `vend doctor --strict`; the
  detailed walkthrough and the offline replay without a key follow.
- [Install](https://github.com/LevapVeeskela/lv24-vending-machine/blob/main/docs/install.md)
  — binary layout, checksums and the unsigned-binary warnings. The release is
  not published yet; a source build is the working path.
- [Live smoke runbook](https://github.com/LevapVeeskela/lv24-vending-machine/blob/main/docs/runbook-live-smoke.md)
  — a 15-minute live check with `doctor --live`, one manual 1m signal and one
  label.
- [Seven days of operation](https://github.com/LevapVeeskela/lv24-vending-machine/blob/main/docs/run-7-days.md)
  — the multi-day shadow run and the G1 criterion, including the
  `g1: labels N/100, active days D/7, max gap Hh` block.

## Known limitations

- **Shadow only.** The gate evaluates, labels and journals; it never sends an
  order. `paper` and `sandbox` are accepted by the config but have no OMS behind
  them yet.
- **Demo is synthetic.** `vend demo` is a walkthrough, not evidence: its journal
  carries `runId=demo`, `status` and `report` print `SYNTHETIC — not G1 evidence`
  with `g1: 0/100, 0/7`, and `gate report --share` refuses it. G1 progress is
  counted only from a real journal and printed as `g1: labels N/100, active days
  D/7, max gap Hh, eligible=yes/no`.
- **Not in this release:** release publication automation, the TradingView
  webhook adapter, desktop/web/mobile clients, paper/live execution and the
  two-way Telegram bot.
- **Verified environment.** The offline end-to-end rehearsal against the local
  stub was run on Windows 11. On Linux, `vend_linux_amd64` was checked under WSL
  Ubuntu with `version`, `init` and `doctor`; the rest of the Linux path was not
  run. macOS was not run at all. The live path with real decision, candle and
  Telegram providers has not been exercised on any platform yet: no real Drex,
  Binance or Telegram endpoint has been called.
- The report describes what the filter would have done with the signals it saw.
  It is not a profit forecast and not investment advice, and it makes no
  promise of return.

## After a week: what to send

Post the output of

```bash
vend gate report --share
```

in [GitHub Discussions](https://github.com/LevapVeeskela/lv24-vending-machine/discussions).
The summary is anonymized: it contains no symbols, venues, prices, position
sizes, state, paths, identifiers or individual returns; the aggregate
ALLOW-vs-REJECT mean return difference and its 95% interval are included. It is
published manually.

**Do not send:** the config, keys or environment variables, the `--save-raw`
file, `vending.db`, `shadow-status.json` with paths, or screenshots that show
keys.
